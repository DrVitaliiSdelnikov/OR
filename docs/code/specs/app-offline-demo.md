# app · офлайн-демо (T5.4)

Статус: реализовано 22.11, ветка `feat/offline-demo`. Решения автора 22.11: демо = обычная сборка (Pro открыт, курс по порядку, «Открыть всё» — в настройках); новая версия ставится тихо при следующем запуске. Логика — решено мной.
Задача бэклога: T5.4. Решения: В41.

## Зачем

Ссылку на демо (GitHub Pages) открывают один раз — дальше тренажёр работает без сети: в поезде, на стрельбище.

## Правила

- Service worker Angular (`@angular/service-worker`) — только в веб-сборке `production`: не в `ng serve` и не в Capacitor (там файлы и так на устройстве).
- Регистрация — когда приложение стабильно, но не позже 30 с после запуска: не мешает первому показу.
- Кеш при первом визите — всё приложение: `index.html`, скрипты, стили, иконка, картинки сцены (`public`, около 1 МБ). Глубокие ссылки (`/course/04`) без сети отдают `index.html`.
- Обновление: новая версия скачивается в фоне и включается при следующем открытии; идущую стрельбу ничто не прерывает.
- Прогресс и так в `localStorage` — сети не требует.

## Готово, когда

- Юнит: SW включён только в продакшене и только в браузере; конфиг кеширует приложение и картинки сцены заранее, навигация отдаёт `index.html`.
- e2e на сборке: первый визит → SW управляет страницей → без сети главный экран и глубокая ссылка открываются, картинки сцены из кеша.
- Мутации на каждый новый тест.

## Как сделано

- `@angular/service-worker` 21.2.25 (как ядро Angular); `angular.json` → `production.serviceWorker: ngsw-config.json`. Workflow GitHub Pages собирает production с `--base-href /<репо>/` — манифест SW строится от него.
- `ngsw-config.json`: группа `app` — `index.html`, `*.js`, `*.css`, `favicon.ico`, шрифты `media/*.woff2` (woff не нужен: все браузеры с SW читают woff2; кеш ~0,65 МБ шрифтов вместо 1,3); группа `scene` — картинки сцены. Обе — `prefetch`.
- `app.config.ts`: `provideServiceWorker('ngsw-worker.js', { enabled: isOfflineCacheEnabled(...), registrationStrategy: 'registerWhenStable:30000' })`; `isOfflineCacheEnabled` — `services/offline.model.ts` (не dev, не Capacitor).
- Тихое обновление — поведение SW Angular по умолчанию, отдельного кода нет.
- `e2e/serve-dist.mjs` отдаёт `.webp` как `image/webp`.

## Отступления

- e2e офлайна — только Chromium: Playwright WebKit (Windows) без сети не отдаёт навигацию через SW, хотя SW управляет страницей. Настоящий Safari SW поддерживает; проверка на iPhone — вручную.
- e2e обязателен на продакшен-сборке (`playwright.build.config.ts`) и пропускается в `ng serve`, где SW нет.
- Шрифты в e2e без сети не проверяются отдельно — их кеш держит юнит на конфиг.
- Во всех e2e, кроме `offline`, регистрация SW заблокирована (`serviceWorkers: 'block'` в `playwright.config.ts`): Playwright WebKit с SW срывал ленивую подгрузку разделов (8 падений в `main-course`, `settings`, `daily`), а эти спеки проверяют логику, не кеш. `offline` включает SW обратно (`test.use({ serviceWorkers: 'allow' })`).
- Готовность кеша в e2e — не «SW активен», а: страница под SW, драйвер `NORMAL` с версией (`/ngsw/state`) и каждый URL манифеста в кеше своей группы. Без этого первый прогон после сборки падал: SW ещё докачивал чанки или инициализировал версию и отвечал 504.

## Мутации

| Тест | Мутация → красный |
| --- | --- |
| `offline.model.spec` | кеш и в разработке; кеш и в Capacitor; шрифты не кешируются; сцена не кешируется заранее; навигация только на `/about` |
