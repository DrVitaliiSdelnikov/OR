# sim/notebook · модель блокнота

Статус: реализовано 7.11, слито в `master`. Юнит-тестов 394, e2e 46 (по 23 на mobile-chromium и mobile-webkit) — все зелёные.
Задача бэклога: S9. Решения: Б2, Б3, Б5, Б11, Б16, Б17, Б17а, Б22, Б23, Б33, В29. Правила: бриф [02](../../design/briefs/02-notebook.md), бриф [03](../../design/briefs/03-calc-sheet.md), [CHECK-RESULT](../../logic/CHECK-RESULT.md), [FORMULAS](../../logic/FORMULAS.md).

## Зачем

Блокнот — рабочий лист позиции: показания приборов → шаги расчёта → итог на барабаны. Сейчас в коде его нет: расчёт размазан по `app/calc`, `app/wind`, `app/dope` (кандидаты на удаление в A5). Нужна одна модель без DOM, на которую сядут шторка и вкладки (A5), проверка (A6) и итог упражнения (S8).

| Что | Для какого экрана |
| --- | --- |
| вкладки и их состояние (пусто · заполнено · устарело) | табы шторки, точки на табах |
| показания: дистанция, станция, ветер, флажки | вкладки ДИСТАНЦИЯ, УСЛОВИЯ, ВЕТЕР |
| АВТО: факторы вкл / выкл и вклад каждого в кликах | хаб ИТОГ в АВТО |
| САМ: шаги со слотами, чипами и лентой арифметики | лист расчёта (03) |
| итог на барабаны и удержание сеткой | липкая строка итога, «ВНЕСТИ НА БАРАБАНЫ» (метки S1) |
| входы проверки после выстрела | экран проверки (C7) |

Слой `src/sim`, без DOM. Видимых изменений нет: экраны садятся на модель в A5.

## Состав модели

```
Notebook
  mode            'auto' | 'manual-easy' | 'manual-hard'
  context         что задано позицией: патрон и его карточка, цель (размер, известна ли дистанция), упражнение (механика), зоны ветра
  readings        что игрок снял с приборов: дистанция (задана или миллинг), замер станции, ввод ветра, флажки
  factors         АВТО: dope · conditions · wind · lead — вкл / выкл и вклад
  steps           САМ: distance · dope · atmosphere · wind (+ zones) · lead — слоты, лента, «записано»
  total           итог на барабаны (ВЕРТ, ГОР) + удержание сеткой (упреждение)
  hasOpenedReference   справочник в сложном (−30, S8)
```

## Правила (решено мной)

### Показания

- **Дистанция.** Известная — задана упражнением. Неизвестная — миллинг: размер цели на сетке в MIL (два касания), Д = размер × 1000 / MIL (`rangeByMilling`). В АВТО — по кнопке, в САМ — шаг «Дистанция».
- **Станция.** Замер удержанием 3 с. Отпустил раньше — показание записано с пометкой «короткий замер» (значение то же, пометка для журнала). Показание хранит время замера. Ветер со станции в поле ветра сам не переносится (Б11). Исключение — «взять со станции» в АВТО упр. 01–03 (флаг механики курса).
- **Ветер.** Скорость с шагом 0,1 м/с, часы — получасы. Пусто, пока игрок не ввёл.
- **Флажки** (упр. 09, 12): V⊥ на 200 / 400 / 600 м по углу флажка. Вместе с V⊥ станции дают средний ветер (C9).

### Цепочка эталонов (Б23)

Каждый шаг проверяется по игровой формуле **от данных игрока на входе шага**, а не от идеала. Ошибка учитывается один раз — там, где возникла. Пример: при миллинге игрок получил 320 м вместо 300. Шаг «Дистанция» — ошибка. Шаги ДОПЕ и ветра считаются верными, если они верны для 320 м.

| Шаг | Эталонные входы | Откуда |
| --- | --- | --- |
| Дистанция | размер цели, MIL на сетке | брифинг, отметка игрока |
| ДОПЕ | ВЕРТ строки карточки на дистанции игрока | `dopeRowAt(card, D игрока)` |
| Атмосфера | T, P замера станции; две колонки строки | замер, карточка |
| Ветер | V и часы — **как ввёл игрок** на вкладке ВЕТЕР; D игрока; K строки | ввод, карточка |
| Ветер по зонам | V⊥ станции и флажков, веса строки (В29) | ввод, флажки, карточка |
| Упреждение | скорость и направление цели из брифинга; t строки; D игрока | брифинг, карточка |

Ошибки ввода (скорость не та, что на станции) ловит не шаг ветра, а строка ПОКАЗАНИЯ подготовки (`reading-speed`, C7).

### АВТО (Б22)

- Факторы: ДОПЕ, УСЛОВИЯ, ВЕТЕР, УПРЕЖДЕНИЕ (только у движущейся цели). По умолчанию включены ДОПЕ и ВЕТЕР.
- Вклад считается у каждого фактора, даже у выключенного: «+2 кл.».
- Итог = сумма включённых, по игровым формулам от показаний игрока.

### САМ (Б17, Б17а)

- **Шаг** = формула + слоты + лента арифметики + сторона + единицы.
- **Слоты** заполняются чипами: тап по чипу — в активный слот, тап по слоту — вынуть.
- **Константа.** В лёгком константа выписана (K и колонки карточки — не слоты). В сложном она в слоте.
- **Чипы:**
  - лёгкий — только нужные, слот знает, какой чип ждёт (подсветка);
  - сложный — нужные + 2 ловушки. Ловушки честные: V рядом с V⊥, дальность соседней цели рядом с D, лишние T и P. Порядок чипов — по зерну, не по ответу.
- **Группы чипов** при > 5 чипах: приборы · расчёт шагов · патрон.
- **Лента** — числа, которые игрок набирает сам. Для ветра: V⊥ × D → ÷ K → до клика; итог шага — последнее число ленты со стороной.
- **«ЗАПИСАТЬ»** — шаг записан. Вердикта нет (Б16).
- **Мягкая подсказка** в лёгком: тип ошибки без ответа («проверь деление»). Берётся из проверки C7 по записанному шагу; правильное число модель наружу не отдаёт.
- **Чипы-результаты шагов.** Результат шага становится чипом «расчёт шагов» для следующих (V⊥ → в W, D → в ДОПЕ и W).

### Устарело (Б33 и шире)

Шаг и фактор помнят снимок входов, по которым записаны. Устарели, если хоть один вход сейчас другой. Причины:
- `cartridge` — сменили патрон: другие карточка, K, колонки, t;
- `distance` — новая цель или новая дистанция;
- `conditions` — новый замер станции;
- `wind` — новый ввод ветра.

Что происходит:
- АВТО пересчитывает сам — вклад факторов всегда свежий.
- САМ: устаревший шаг очищается, остаётся пометка «устарело · патрон сменён» (причина — первая из списка). Барабаны не трогаются (Б33).
- Карандашные записи ДОПЕ привязаны к патрону и не слетают — они в журнале (S8 / A7), блокнот показывает записи текущего патрона.

### Итог

- **На барабаны** — ВЕРТ = ДОПЕ + атмосфера (если учтена), ГОР = ветер. Переводит в клики `turretTarget` (S1): упор → остаток в удержание.
- **Сеткой** — упреждение (М1) и остаток при упоре.
- Итог «пусто», пока нет ДОПЕ. Ветер не введён → ГОР 0 и вкладка ВЕТЕР с точкой.

### Вкладки

ИТОГ · ДИСТАНЦИЯ · УСЛОВИЯ · ВЕТЕР · ДОПЕ. Точка — вкладка не заполнена:
- ДИСТАНЦИЯ — неизвестная дистанция не измерена;
- УСЛОВИЯ — нет замера;
- ВЕТЕР — ветер не введён;
- ДОПЕ — никогда.

Закрытые УГОЛ · ПАТРОН · ЕЩЁ — по механике курса (S8), «откроется в упр. N».

## Граничные случаи

- Шаг ДОПЕ при дистанции вне карточки (< 100 или > 1000 м) — ZERO STOP и удержание (набор И), не ошибка модели.
- Ветер с 12 или 6 ч — W = 0, шаг ветра в САМ всё равно есть (доля 0 — тоже расчёт).
- Неподвижная цель — шага и фактора «Упреждение» нет.
- Зон нет — шаг «ветер по зонам» не показывается, ветер одной строкой.
- `placeChip` в заполненный слот — заменяет чип.
- `recordStep` с пустым слотом — нельзя (`RangeError`): «ЗАПИСАТЬ» неактивна.
- Повторный замер станции после записанного шага атмосферы — шаг устарел (`conditions`).
- Смена режима после первого выстрела по цели — забота экрана и `FiringLine` (множитель, S8); модель режим не запирает.

## Как сделано

- Модель — простые неизменяемые объекты и функции; каждая операция возвращает новый блокнот (`Notebook`).
- Шаги САМ описаны таблицей `STEPS`: слоты, константы (в сложном — тоже слоты), ловушки по приоритету, длина ленты, от чего зависит шаг. Шаг «зоны» (V⊥ср) — отдельный, его результат становится чипом V⊥ шага ветра.
- `placeChip(…, slotIndex?)`: без номера слота — в первый пустой.
- Запись шага «Дистанция» ставит дистанцию игрока — дальше по цепочке все шаги берут её (Б23), а записанные раньше устаревают по причине `distance`.
- «Устарело»: шаг помнит патрон, дистанцию и номера замера станции и ввода ветра; при изменении — очищается с причиной (порядок: патрон → дистанция → условия → ветер).
- В `calc-check` добавлен вид шага `zones`: его разница считается в кликах ветра.
- Знаки: ветер слева — V⊥ плюс, поправка влево — минус; барабан ГОР в кликах «влево» (как `ScopeSession`), удержание переводится обратно в «вправо — плюс».
