# app · журнал с величинами причин (T2.3)

Статус: реализовано 18.11, ветка `feat/journal-causes`; согласовано пользователем 17.11.
Задача бэклога: T2.3. Решения: В39 (рейтинг по навыкам из журнала), В55 (ответы 17.11: везде а). Перед: T2.1 (цепочка подстановок), T2.2 (лестница причин). Дальше: T4.1 (рейтинг по навыкам), T4.2 (прошлые выстрелы журнала один раз прогоняются в рейтинг).

## Зачем

Сейчас журнал хранит для выстрела только грубую причину: «расчёт», «ветер», «удержание»… Рейтингу по навыкам (T4.1) нужно знать, какой шаг ошибся и насколько: «дальность — 0,6 MIL». Если начать писать это сейчас, к T4.2 в журнале уже накопятся выстрелы с величинами. Старый прогресс при обновлении не должен потеряться.

## Правила (решено мной)

### Что пишется в выстрел

- `JournalShot.causes?: { kind: CauseKind; mil: number }[]` — причины игрока из лестницы T2.2: звенья цепочки (кроме округления) и исполнение (удержание, упреждение сеткой, спуск, ноль прицела).
- `mil` — модуль вектора причины, округлённый до 0,01 (см. «Отступления»). Причины, у которых после округления 0, не пишутся. Серые причины (формула против ядра, винтовка, холодный ствол) не пишутся: это не ошибки игрока.
- `JournalShot.clickMil?: number` — цена клика прицела. По ней T4.1 переводит MIL в клики («звено больше 1 клика — ошибка навыка»): у своей винтовки клик бывает 0,1 MIL или ¼ MOA.
- Попадание тоже пишется с причинами: попасть можно и с ошибкой дальности в 1 клик, рейтингу это важно. Во вкладке «Ошибки» на попадании считаются только звенья расчёта (В58).
- Грубая `mainCause` остаётся: по ней работают итог, вкладка «Ошибки» и старые записи.
- Поля необязательные. Нет `causes` — выстрел из старой версии, величины неизвестны. Пустой массив — выстрел без ошибок игрока. T4.2 не должен засчитывать старые выстрелы как чистые.

### Откуда

`ExerciseShotRecord` получает `causes` и `clickMil` в `PositionSession.fire()` из `missBreakdown` и `clickMil` карточки. Помогает чистая `journalCauses(breakdown)` в `sim/miss-breakdown.ts`. Дальше `journalSeries` переносит поля в `JournalShot`.

### Хранилище v2

- Ключ `or.progress.v2`, в состоянии `version: 2`.
- Загрузка: если есть v2, читается он. Иначе читается v1, прогоняется через чистую `migrateProgress(v1)` → v2 и сразу записывается. Ключ v1 не удаляется и не меняется: это резервная копия на случай отката, её же берёт T4.2 (`backup.or.progress.v1`).
- `migrateProgress`: переносит курс, настройки, журнал, заметки ДОПЕ, свободную игру и профили как есть. Выстрелы журнала остаются без `causes`. Битые поля отбрасываются по прежним правилам `load()`.
- Сброс прогресса и запись идут только в v2.
- В e2e помощники кладут прогресс в v2. Отдельный e2e кладёт только v1 и проверяет, что журнал и курс на месте.

## Решения пользователя (В55, 17.11) — везде а)

1. **Лента журнала.** Строка промаха сейчас: «3 · 600 м · мимо — ошибка расчёта». Варианты:
   - а) как в разборе, звено с величиной: «мимо — дальность, 0,6 MIL»;
   - б) оставить грубую причину, величины пока только копить для рейтинга.

   Предлагаю а). Старые записи без величин покажут прежнюю фразу.
2. **Вкладка «Ошибки».** Сейчас она считает ошибки проверки расчёта (сторона, подстановка…) и грубые причины исполнения (удержание, спуск, ветер). Варианты:
   - а) считать по звеньям, где звено больше клика: «Скорость ветра ×5, Дальность ×3, Удержание ×2»; ошибки проверки расчёта остаются как есть;
   - б) оставить как есть до T4, где появится экран навыков.

   Предлагаю а).
3. **Итог упражнения.** Строка «3 из 5 — ошибка расчёта». Варианты:
   - а) по звеньям: «3 из 5 — скорость ветра»;
   - б) оставить грубо.

   Предлагаю а), по той же главной причине, что и в разборе.

## Готово, когда

- Юнит: `journalCauses` (округление до 0,05, без нулей, без серых и округления); `journalSeries` переносит `causes` и `clickMil`; `migrateProgress` на снимке v1 даёт v2 без потерь (курс, настройки, 3 серии, заметки, профили); `ProgressStore.load` читает v2, иначе мигрирует v1 и пишет v2, v1 не трогает.
- e2e: в хранилище только v1 → журнал и курс на месте; выстрел в 06 → в v2 у выстрела есть `causes`.
- Если по вопросам выбрано а) — e2e ленты, вкладки «Ошибки» и итога на звеньях.
- Мутации на каждый новый тест.

## Как сделано

- `sim/miss-breakdown.ts`: `CauseAmount { kind, mil }`; `journalCauses(breakdown)` — причины игрока (без серых и округления) до 0,01 MIL, без нулей, в порядке лестницы; `mainOfAmounts(causes, clickMil)` — главная из записанных (от клика, ничья — раньше по лестнице), совпадает с `breakdown.main`; `CAUSE_ORDER` — постоянный порядок причин.
- `ExerciseShotRecord.causes` и `clickMil` пишет `PositionSession.fire()`; `journalSeries` переносит их в `JournalShot` только вместе.
- Лента: промах — «Дальность, 0,6 MIL» (`screens.journal.shotCause`); причины от клика нет — без причины; старая запись — прежняя фраза.
- «Ошибки»: звенья от клика на каждом выстреле, и на попаданиях; ключ строки `link:<kind>` (`errorRowCause` даёт термин учебника); накрутку и расчёт упреждения, уже отмеченные проверкой расчёта (`turret`, `lead`), выстрел второй раз не считает. Старые записи — грубые причины исполнения, как раньше.
- Итог: если у всех выстрелов есть величины — «3 из 5 — скорость ветра» (главная каждого выстрела, ничья — по `CAUSE_ORDER`, название со строчной через `lowerFirst`); иначе — прежняя грубая строка.
- `ProgressStore`: ключ `or.progress.v2`, запись с `version: 2`; нет v2 — читается v1 через `migrateProgress` и сразу пишется v2; v1 не меняется и не удаляется; битый v2 удаляется, битый v1 — нет. e2e-помощники пишут v2, `seedProgress` принимает ключ.

## Отступления от спеки (решено мной)

- Точность 0,01 MIL вместо 0,05: при клике 0,1 MIL величина 0,04 (в разборе 0 кликов) округлялась до 0,05 = полклика и считалась кликом — журнал расходился бы с разбором.
- Найдено на e2e: ключ звена «накрутка» совпадал с ошибкой проверки «БАРАБАН», один выстрел считался дважды. Ключи звеньев отделены, а дубли проверки и звена не считаются.
- Итог в e2e не проверяется — дойти до итога с нужными промахами в UI долго и неустойчиво; покрыт юнит-тестами `result.model.spec`.
- В e2e перекрут на 8 кликов: на webkit 20 кликов не укладываются в время теста. В 01 «Внести на барабаны» не накручивает, а ставит задачу «крути вверх: ещё 16 кл.», поэтому 20 кликов — перекрут на 4 клика, 0,4 MIL (выяснено в Chrome 18.11). С 8 кликами накрутка — недокрут на 8 кликов; тест проверяет только, что звено записано.

## Мутации

| Тест | Мутация → красный |
| --- | --- |
| `miss-breakdown.spec` | серые причины в журнале; без округления; нули остаются; главная и меньше клика; ничья — последняя |
| `position-session.spec` | в записи нет причин; нет цены клика |
| `journal.model.spec` | серия не переносит причины; лента всегда грубо; без главной — первая причина; звенья без порога клика; проверенное считается второй раз; ключ звена = ключ проверки; грубые причины и у новых; на попаданиях не считается |
| `result.model.spec` | итог всегда грубо; по звеньям и со старыми записями; название с заглавной; ничья — последняя |
| `progress.store.spec` | v2 = ключ v1; после переноса v2 не пишется; без версии; битый v2 не удаляется; v2 не читается |
| e2e `journal-causes` (chromium) | лента всегда грубо; проверенное считается второй раз; после переноса v2 не пишется; в записи нет причин |

## Изменение 18.11 (В58, найдено в Chrome)

После 01 с тремя попаданиями итог писал «Ошибок нет», а «Ошибки» — «Удержание ×3»: увод на клик на каждом попадании. Решение пользователя — а): на попадании исполнение (удержание, упреждение сеткой, спуск, ноль) не ошибка, считаются только звенья расчёта; у старых записей грубая причина исполнения на попадании тоже не считается. В журнал причины пишутся как раньше — для рейтинга.

| Тест | Мутация → красный |
| --- | --- |
| `journal.model.spec` | исполнение на попаданиях считается; на попаданиях не считается ничего; старые записи на попаданиях считаются |
