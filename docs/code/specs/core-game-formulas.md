# core/game-formulas · правило часов · дальность 1000 м

Статус: реализовано 7.11, слито в `master`. Юнит-тестов 163, e2e 46 (по 23 на mobile-chromium и mobile-webkit) — все зелёные.
Задачи бэклога: C1, C2, C3. Решения: Б15, Б32, Б11, М1, В8.
Правила: [FORMULAS.md](../../logic/FORMULAS.md) — единственный источник формул и чисел. Здесь только то, как это ложится в код.

## Зачем

Игровые формулы, по которым игрок считает в блокноте и по которым игра проверяет его расчёт (САМ) или считает за него (АВТО). Пуля по-прежнему летит по ядру (`engine.ts`). Модуль чистый TS, без DOM и без Angular — слой `src/core`.

## Публичный интерфейс `game-formulas.ts`

| Функция | Вход | Выход | Формула (FORMULAS) |
| --- | --- | --- | --- |
| `rangeByMilling(targetSizeM, sizeOnReticleMil)` | м, MIL | м | «Дальность» |
| `isRangeWithinTolerance(estimatedM, trueM, tolerance)` | м, м, доля (0,05 / 0,10) | boolean | «Дальность», допуски |
| `crosswindMps(speedMps, clockHours)` | м/с, часы | м/с, без знака | V⊥ = V × доля |
| `windCorrectionMil(speedMps, clockHours, distanceM, windConstant)` | м/с, часы, м, K | MIL со знаком: ветер слева (7–11 ч) → минус (брать влево), справа (1–5 ч) → плюс, как в ядре | W = V⊥ × D / K |
| `atmosphereCorrectionMil(row, temperatureC, pressureHpa)` | строка карточки, °C, гПа | MIL | заменено в C4 ([core-calibration](core-calibration.md)): по колонкам строки вместо K_атм |
| `leadMil(targetSpeedMps, movementClockHours, timeOfFlightS, distanceM)` | м/с, часы направления движения, с, м | MIL без знака (сторону упреждения выбирает слой app по направлению движения) | «Движущиеся цели» |
| `roundToClicks(mil, clickMil)` | MIL, цена клика | целое число кликов, половина — от нуля | «Единицы» |
| `clicksDifference(playerMil, referenceMil, clickMil)` | MIL, MIL | целое ≥ 0 | для проверки расчёта (CHECK-RESULT) |

Знаки — как в ядре: вправо и вверх = плюс. Перевод в «← L / → R» и стрелки — дело слоя `app`.

## Граничные случаи

- Доля по часам: 0 и 12 — одно и то же; значения вне 0–12 нормализуются по модулю 12; отрицательные часы тоже.
- Доля округляется до двух знаков (0,866 → 0,87), чтобы совпадала с таблицей FORMULAS и подсказками.
- `rangeByMilling` при 0 MIL — ошибка (`RangeError`), а не бесконечность.
- `roundToClicks(0.35, 0.1)` = 4; `roundToClicks(-0.35, 0.1)` = −4 (половина — от нуля); защита от ошибок плавающей точки (0,35 / 0,1 = 3,4999…).
- `windCorrectionMil` при штиле — 0, с 12 и 6 ч — 0, при дистанции 0 — 0.
- Траектория 1000 м: сохраняются все прежние проверки на 100–700 м; запрос дальше 1000 м — ошибка, как раньше дальше 700.

## Пользовательские тесты

Модуль не виден напрямую. Видимое следствие одно — экран ветра (`app/wind`):

| # | Сценарий | Устройства |
| --- | --- | --- |
| E1 | ветер с 2 ч, 4 м/с → доля 0,87, боковой 3,5 м/с | mobile-chromium, mobile-webkit |
| E2 | ветер с 1:30 → доля 0,71 | mobile-chromium, mobile-webkit |

Экран ветра потом переедет во вкладку блокнота (Б11); тогда сценарии переносятся в его спеку.

## Проверка на устройствах

- Юнит-тесты — `vitest` (node), от устройства не зависят.
- Для E1 и E2 в `playwright.config.ts` добавить проект `mobile-webkit` (iPhone 14) и скрипт `start:lan` (`ng serve --host 0.0.0.0`) для открытия на телефоне. Установка браузера WebKit для Playwright — один раз: `npx playwright install webkit`.
- На настоящем телефоне — открыть экран ветра и проверить, что доля и боковой ветер совпадают с таблицей FORMULAS.
