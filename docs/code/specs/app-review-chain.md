# app · лестница причин в разборе и красный карандаш в блокноте (T2.2)

Статус: реализовано 17.11, ветка `feat/review-chain`; согласовано пользователем 17.11.
Задача бэклога: T2.2. Решения: В40 (разбор промаха цифрами), В12 (порядок разбора), В52 (ответы 17.11, см. ниже). Перед: T2.1 (цепочка подстановок, `MissBreakdown.chain`). Дальше: T2.3 (журнал с величинами).

## Зачем

T2.1 посчитала, какой шаг увёл пулю, но игрок этого пока не видит: в разборе по-прежнему «ошибка расчёта, 4 клика». T2.2 выводит цепочку на экран — в разбор («Почему ушла пуля») и в блокнот, где игрок исправляет расчёт перед следующим выстрелом.

## Решения пользователя (В52, 17.11)

1. **Одна лестница.** Все причины игрока по убыванию вклада: звенья расчёта (дальность, скорость ветра…) и исполнения (удержание, спуск, упреждение сеткой) вперемешку. Крупнейшая — первой и красным. Не ошибки (формула против ядра, винтовка, холодный ствол) — серым внизу.
2. **Только ненулевые.** Видны причины от клика. Удержание и спуск видны всегда (как сейчас: «чисто»), чтобы было видно, что исполнение в порядке.
3. **«Было / надо» сразу в строке.** Под названием мелко, в единицах игрока: «2 вместо 4,1 м/с», «413 вместо 455 м», «ВЕРТ 3,8 вместо 3,5 MIL».
4. **Красный карандаш на шаге с ошибкой.** В САМ — на строке шага в хабе и в листе шага. В АВТО — на вводе: скорость и час ветра, дальность. Держится до пересчёта или следующей цели.

## Правила (решено мной)

### Лестница

| Причина | Строка | «Было / надо» |
| --- | --- | --- |
| дальность | «Дальность» | «413 вместо 455 м» |
| строка ДОПЕ | «Строка ДОПЕ» | «ВЕРТ 3,8 вместо 3,5 MIL» |
| условия | «Условия» | «+0,1 вместо +0,3 MIL» |
| угол | «Угол места» | MIL |
| вращение | «Деривация и Кориолис» | MIL по горизонтали и вертикали |
| скорость ветра | «Скорость ветра» | «2 вместо 4,1 м/с» |
| часы ветра | «Час ветра» | «2 ч вместо 3 ч» (правда — до получаса) |
| зоны | «Флажки» | «1 · 3 · 1 вместо 1 · 1 · 1 м/с» |
| ветер: расчёт | «Расчёт ветра» | MIL |
| упреждение (расчёт) | «Упреждение: расчёт» | MIL |
| накрутка | «Барабаны» | «накручено 37 вместо 35 кл.» |
| округление | не показывается: всегда меньше клика | — |
| удержание, спуск, упреждение сеткой, ноль | как сейчас | — |
| формула, винтовка, холодный ствол | серым, как сейчас | — |

- Вклад строки — клики, как сейчас, и полоска по доле от крупнейшей.
- Вывод сверху называет крупнейшую причину: «Скорость ветра: 2 вместо 4,1 м/с — ← 3 кл.», с прежней припиской про чистый спуск.
- Лепестки `calc` и `wind` уходят из разбора: их заменяют звенья. Звено упреждения вычитается из лепестка исполнения «упреждение». Сумма строк по-прежнему равна попаданию.
- **Итог упражнения и журнал** пока считают главную причину по прежним грубым категориям: «расчёт», «ветер мало / много», «упреждение», «удержание», «спуск», «ноль». Категория собирается из звеньев. Величины в журнале — T2.3.

### Красный карандаш

- После выстрела позиция запоминает звенья разбора с вкладом от клика. Метка стоит на месте, где игрок может исправить:

| Звено | САМ | АВТО |
| --- | --- | --- |
| дальность | шаг «Дальность» | вкладка «Дистанция», результат миллинга |
| строка ДОПЕ, условия, угол, вращение, упреждение | свой шаг | — (считает блокнот) |
| скорость, час ветра, флажки | шаг «Ветер» (или «Ветер по зонам») | вкладка «Ветер»: скорость, час, флажок |
| расчёт ветра | шаг «Ветер» | — |
| накрутка | — (видна в «Проверке расчёта») | — |

- Метка — «надо 3,5» (или «надо 4,1 м/с») красным карандашом рядом со значением игрока; значение игрока зачёркнуто.
- Метки снимаются, когда игрок пересчитал шаг (шаг устарел или записан заново), перешёл к следующей цели или начал перерасчёт.

## Как сделано

- `sim/miss-breakdown.ts`: причины = звенья `chain` (звено `lead` → причина `lead-calc`) + исполнение (`hold`, `lead`, `trigger`, `zero`) + серые. `chain` обязателен, `formulaPlayerWind` и лепестки `calc` / `wind` удалены. Звено упреждения вычитается из лепестка `lead`, сумма причин по-прежнему равна попаданию. `MissCause.link` — звено строки. `main` — крупнейшая ошибка игрока от клика по всей лестнице; `mainCause` — грубая категория для итога и журнала: «расчёт» = дальность, ДОПЕ, условия, угол, вращение, расчёт ветра, округление, накрутка; «ветер» = скорость, час, флажки (недокрут или перекрут по стороне правды); «упреждение» = звено + лепесток. `MissBreakdown.clickMil` — для кликов накрутки.
- `sim/miss-chain.ts`: у звена вращения — `parts` по деривации, Кориолису и Этвёшу; у накрутки величина `dial`: барабан игрока и план без удержания.
- `sim/pencil-marks.ts`: `pencilMarksAfterShot(notebook, chain)` — метки звеньев от клика по местам (таблица выше); `withoutStaleMarks` снимает метку, если место изменилось. Место — шаг САМ целиком или ввод АВТО: миллинг, ветер (скорость и час вместе), флажки.
- `PositionSession`: метки ставятся после выстрела, стираются на новой цели; `pencilMarks()` сверяет их с блокнотом. Перерасчёт — новая сессия без меток.
- `app/review/review.model.ts`: `causesView(breakdown, system)` — строки игрока по убыванию кликов, серые ниже; `values` — «было / надо»; `chainValuePair` форматирует пару по виду величины (её же берёт карандаш). Вывод: «Название: было / надо — сдвиг», для исполнения — прежние фразы.
- `app/notebook/pencil.model.ts` + `pencil-note.component.ts`: значение игрока зачёркнуто, «надо …» красным; несколько меток места — через точку. Хаб САМ (`step-pencil-*`), лист шага (`calc-pencil`), вкладка «Дистанция» (`milling-pencil`), вкладка «Ветер» (`pencil-wind-speed`, `pencil-wind-clock`, `pencil-flags`).
- Тексты: названия строк, `valuesInstead`, `turretValues`, `linkCause`; термины учебника для новых строк (`termLinks.causes`).

## Отступления от спеки (решено мной)

- «Было / надо» для MIL — со стрелкой стороны, как в листе проверки: «↑ 3,8 вместо ↑ 3,5 MIL», а не «ВЕРТ» или «+». Если при одном знаке значения совпали бы, показываются два.
- Строка исполнения упреждения называется «Упреждение сеткой», чтобы не путать с «Упреждение: расчёт».
- Лепесток упреждения и ноль прицела, как и звенья, видны от клика; всегда видны только удержание и спуск (решение 2).
- Метка шага САМ снимается при любой правке шага: шаг перестаёт быть записанным.
- e2e САМ проверяет ошибку строки ДОПЕ, а не скорости ветра: в САМ шаг «Ветер» считает и скорость, и расчёт, и такой сценарий в UI неустойчив. Метка скорости ветра проверена в e2e АВТО (05, ветер не введён) и в юнит-тестах.
