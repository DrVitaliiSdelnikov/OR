## Зачем

Логика, на которой держатся разбор, проверка, итог упражнения, курс и журнал:
- **оценка:** очки за цели и расчёт, итог серии, класс упражнения, звание;
- **проверка расчёта:** статус каждого шага, тип ошибки, вердикт и главная ошибка.

Оба модуля чистые, без DOM: слой `src/core`. Числа на вход (MIL, клики) готовит вызывающий код — блокнот, сессия прицела (S9, S1).

## core/calc-check.ts

### САМ: проверка шагов

Вход — шаги расчёта, которые игрок записал до выстрела:

```ts
interface CalcStepInput {
  step: 'distance' | 'dope' | 'atmosphere' | 'wind' | 'lead';
  expectedInputs: readonly number[];   // что должно стоять в слотах формулы
  playerInputs: readonly number[];     // что игрок поставил
  expectedRawMil: number;              // результат формулы до округления, со знаком
  playerMil: number;                   // ответ игрока, со знаком
  playerUnits: 'mil' | 'moa';
}
```

Для шага «дистанция» вызывающий код переводит метры в MIL итога через карточку (CHECK-RESULT: «оцениваются по тому, на сколько кликов сдвинули бы итог»).

**Статус шага** по разнице в кликах между ответом и округлённым результатом формулы (`clicksDifference`, C3): 0 — верно; 1 при верной стороне — почти; 2 и больше — ошибка. Перепутанная сторона и не те единицы — всегда ошибка.

**Типы ошибок шага** (одного шага может быть несколько, по порядку важности):

| Тип | Когда |
| --- | --- |
| ЕДИНИЦЫ | `playerUnits` ≠ MIL |
| ПОДСТАНОВКА | в слотах не те числа |
| СТОРОНА | оба значения ненулевые, а знаки разные |
| ОКРУГЛЕНИЕ | слоты верны, ответ — соседний клик сырого результата (например, 0,652 → игрок 0,6 вместо 0,7); статус всегда «почти» |
| АРИФМЕТИКА | слоты верны, ответ отличается не из-за округления |
| УПРЕЖДЕНИЕ | любая из ошибок ПОДСТАНОВКА / ОКРУГЛЕНИЕ / АРИФМЕТИКА на шаге «упреждение» называется УПРЕЖДЕНИЕ (CHECK-RESULT) |

ФОРМУЛА — после первого релиза (Б17).

### АВТО: проверка подготовки

```ts
interface PreparationRowInput {
  row: 'reading-speed' | 'reading-direction' | 'factors' | 'turret-elevation' | 'turret-windage';
  clicksOff: number;        // влияние на итог в кликах, вызывающий код считает по формулам
  isWrongSide: boolean;     // только для барабанов
}
```

Эталон каждой строки (Б23): показания — против прибора, факторы — против тех, что дают ≥ 1 клик, барабаны — против итога блокнота игрока. Тот же статус по кликам. Типы: ПОКАЗАНИЯ, ФАКТОР, БАРАБАН, СТОРОНА.

### Результат проверки (общий)

```ts
interface CheckResult {
  verdict: 'exact' | 'close' | 'error';     // худший статус
  rows: readonly CheckedRow[];              // статус, типы ошибок, клики
  mainError: { rowIndex: number; type: ErrorType } | null;
  otherErrorsCount: number;
  counts: { exact: number; close: number; error: number };
}
```

**Главная ошибка (Б25):** самая тяжёлая (ошибка тяжелее «почти»), при равной тяжести — первая по порядку шагов. Остальные считаются в `otherErrorsCount`.

## Граничные случаи

- Ответ 0 при эталоне 0 — верно; ответ 0 при эталоне ≠ 0 — не СТОРОНА, а разница в кликах.
- Пустой расчёт (ни одного шага) — `verdict: 'exact'`, нет ошибок; вызывающий код не должен звать проверку без шагов, но модуль не падает.
- `targetPoints([])` — 0 (по цели не стреляли).
- `seriesTotal` с отрицательным результатом после −30 — 0.
- `exerciseClass` на границе: ровно 70 % → 3 класс, ровно 85 % с целью → 2 класс (сравнение с допуском плавающей точки).
