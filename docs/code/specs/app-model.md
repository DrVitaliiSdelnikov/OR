# app · экран «Модель» (T5.3)

Статус: реализовано 22.11, ветка `feat/model`. Продуктовые решения — автор 22.11: вход из Учебника и с «О приложении»; таблица сверки — выбор патрона и набора условий, одна таблица 100–1000 м. Логика — решено мной.
Задача бэклога: T5.3. Решения: В37 (честная модель, сверка с эталоном). Перед: T1.3, T1.4.

## Зачем

Опытный стрелок должен видеть, что ядро учитывает, где упрощает и насколько расходится с независимым эталоном. Игрок — какими формулами считает сам и насколько они точны против ядра.

## Правила

### Экран `/model`

Заголовок «Модель и сверка». Четыре раздела по порядку:

1. **Что учитывает ядро:** модель точечной массы (`js-ballistics`, движок `bclibc`); сопротивление G7 / G1, BC в ICAO или ASM; атмосфера (температура, давление на станции, влажность, высота через давление); ветер по зонам дистанции и во времени; угол места; деривация (шаг и направление нарезов, длина пули); Кориолис (широта, азимут).
2. **Допущения:** стандартные кривые G7 / G1, а не измеренная кривая пули; ветер только горизонтальный; без аэродинамического прыжка; ноль ровный, в стандартной атмосфере ICAO; скорость у дула постоянная (длина ствола и температура пороха не учитываются); высота влияет только через давление.
3. **Игровые формулы рядом с ядром:** по строке на шаг — дальность, ветер, атмосфера, угол, деривация, Кориолис, упреждение. В строке: формула игрока, как это считает ядро, точность против ядра (числа — из `docs/logic/FORMULAS.md`). Формулы — в системе единиц игрока (имперские: ярды, mph, °F, inHg).
4. **Сверка с эталоном:**
   - источник: библиотека и версия, решатель, дата генерации — из JSON эталона;
   - допуск до 1000 м: возвышение ≤ 0,1 MIL, вбок ≤ 0,05 MIL, время ≤ 1 % (под углом ≤ 1,5 %);
   - чипы патрона (4) и набора условий (3); по умолчанию первый патрон и первый набор;
   - таблица 100–1000 м: ДИСТ · ВЕРТ ядро · ВЕРТ эталон · Δ ВЕРТ · Δ ВБОК · Δ t (%); дистанция — в единицах игрока;
   - итог: наибольшие |Δ| по трём колонкам и «в допуске» / «вне допуска»;
   - пока ядро считает — «Считаю…»;
   - под таблицей — что выровнено для честного сравнения (ровный ноль, BC по ICAO, прыжок вынесен) и, для набора с углом, где модели расходятся.

Числа эталона — из `src/core/reference/*.json`; числа ядра считаются на устройстве при выборе набора тем же способом, что и в тесте сверки T1.3.

### Входы

- Учебник: строка «Модель и сверка →» под главами.
- «О приложении»: такая же строка под пунктами (сами пункты без ссылок, как в app-about).
- «Назад» — шаг по стеку; без истории — в Учебник.

### «О приложении»

Сделанное уходит из «В планах» в пункты: дрилы, рейтинг и тренер, задание дня — новый пункт «Дрилы и задание дня»; экран «Модель» — в пункт «Настоящая баллистика». Пунктов становится 10.

## Готово, когда

- Юнит: эталоны 4 × 3 с названиями в каталоге; сравнение набора — 10 строк, Δ = ядро − эталон, итог и допуск (под углом — 1,5 %); вне допуска — «вне допуска»; таблица в метрах и ярдах; формулы метрические и имперские; ноль в °C / °F.
- e2e: Учебник → «Модель и сверка» → 4 раздела, таблица 10 строк, итог «в допуске»; смена патрона и набора меняет ячейку эталона на число из JSON; «О приложении» → модель → назад; имперская система — дистанции в ярдах.
- Мутации на каждый новый тест; проверка в Chrome.

## Как сделано

- `core/reference-check.ts`: `REFERENCE_TABLES` (4 JSON эталона, .308 первым), `comparedRows(engine, table, set)` — тот же прогон, что в `reference.spec.ts`, строка: ядро, эталон, Δ ВЕРТ, Δ ВБОК, Δ t (доля со знаком); `comparisonSummary(rows, lookAngleDeg)` — наибольшие |Δ| и допуск `REFERENCE_TOLERANCE`.
- Тексты — `i18n/ru/model.ts`: эффекты, допущения, 7 формул (метрика / имперские), названия патронов и наборов, заголовки таблицы.
- `app/model/model.model.ts`: чипы, подпись набора из его данных (высота, ветер, угол, широта) в единицах игрока, источник, допуск, таблица, итог, формулы с диапазонами точности через форматтеры единиц, допущения с нулём в °C / °F.
- `model.page.ts`, маршрут `/model`: `resource` пересчитывает строки ядра при смене патрона или набора; пока считает — «Считаю…»; пояснение про угол — только для набора с углом.
- Входы: `textbook-model` под главами Учебника и `about-model` под пунктами «О приложении», текст общий (`model.link`).
- «О приложении»: пункт «Дрилы и задание дня» (пунктов 10), в «Настоящей баллистике» — ссылка словами на экран «Модель»; из «В планах» убраны дрилы, тренер, задание дня, «Модель».

## Отступления от спеки

- «В планах» не чистили в T3.5, T4.3 и T5.1, хотя app-about этого требует; убрано здесь разом.
- `reference.spec.ts` не переписан на `comparedRows`: тест T1.3 остаётся независимым от экрана.

## Мутации

| Тест | Мутация → красный |
| --- | --- |
| `reference-check.spec` | .308 не первым; эталон пропущен; ядро = эталон по ВЕРТ; вбок без знака ядра; Δ вбок = 0; Δ t без знака; эталон ВЕРТ сдвинут; итог без модуля; допуск ВЕРТ / вбок / время не проверяется; время под углом как на ровной |
| `model.model.spec` | выбран любой патрон / набор; высота, допуск, дистанция, скорость ветра, ноль — всегда в метрике; дата как в JSON; Δ ВЕРТ без знака; Δ t долей; вердикт всегда «в допуске»; формулы всегда метрические |
| `about.spec` | задание дня осталось в планах; нет пункта «Дрилы и задание дня» |
| e2e `model` | нет ссылки из Учебника / с «О приложении»; «назад» не работает; чип патрона / набора не выбирает; пояснения про угол нет; ядро не пересчитывается при выборе; таблица и формулы в метрах всегда; итог не выводится |

Связанные юнит-спеки (`core/reference-check`, `app/model`, `i18n`, `app/textbook`, `units-guard`) — зелёные, кроме старого `catalog-guard` / `index.html`. e2e на сборке `model`, `about`, `textbook`, `term-links`: chromium 15, webkit 15.
